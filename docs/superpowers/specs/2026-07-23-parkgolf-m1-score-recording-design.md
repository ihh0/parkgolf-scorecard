# 파크골프 스코어 앱 — M1(스코어 기록 코어) 설계서

- **작성일**: 2026-07-23
- **상위 프로젝트**: 파크골프 스코어 앱 (전체 명세: `파크골프_앱_프로젝트_명세서.md`)
- **본 문서 범위**: 마일스톤 1 — 스코어 기록 코어

---

## 1. 마일스톤 분해 (전체 로드맵)

전체 앱은 규모가 커서 3개 마일스톤으로 나누고, 각 마일스톤은 자체 명세 → 계획 → 구현 사이클을 가진다.

- **M1 · 스코어 기록 코어** (본 문서): 백엔드 불필요, 100% 오프라인, 로컬 저장. 단독 출시 가능. 핵심 가치(동선 단순화 + 입력 부담 최소화)를 이 단계에서 완성.
- **M2 · 구장 정보 & 클라우드**: 공공데이터 기반 위치·주변 구장, 크라우드소싱 구장 상세, 즐겨찾기, 지도 연동, 클라우드 백업/동기화, 간편 로그인.
- **M3 · 확장**: iOS(로직 공유 검토), 접근성 고도화, 추가 통계.

M2·M3는 본 문서의 범위가 아니다. 단, 아래 설계는 M2 확장을 막지 않도록 자리(예: 시작 화면의 "주변 구장" 섹션)를 남겨둔다.

## 2. M1 목표와 성공 기준

**한 줄 정의**: 백엔드 없이 완전 오프라인으로 도는, 시니어용 초간단 파크골프 스코어 기록 앱.

**성공 기준**
1. 단골 사용자가 앱 실행 후 **2탭 이내에 홀 입력 화면에 도달**한다.
2. 파로 끝낸 홀은 **점수를 손대지 않고** 다음 홀로 넘어갈 수 있다.
3. 최대 4인(나 + 동반자 3)의 스코어를 한 흐름에서 기록한다.
4. **통신이 전혀 없어도** 라운드 시작·입력·저장·조회가 모두 동작한다.
5. 구형·저사양 기기와 다양한 화면 비율에서 레이아웃이 깨지지 않고 안정적으로 동작한다.

**M1 제외 (Out of Scope)**
- 구장 검색·공공데이터·지도·위치, 주변 구장
- 클라우드 동기화/백업, 회원가입·로그인
- 음성 입력
- 커뮤니티·예약·쇼핑·뉴스·AI 등 부가기능 일체

## 3. 기술 스택 · 아키텍처

- **언어/플랫폼**: Kotlin, 네이티브 Android.
- **UI**: **View 시스템(XML 레이아웃) + ConstraintLayout**. 비율·가이드라인·퍼센트 제약으로 다양한 화면비에 대응하고, 구형·저사양 기기에서 검증된 안정성을 확보한다. (RelativeLayout은 레거시이므로 사용하지 않고 ConstraintLayout로 대체) **ViewBinding** 사용.
- **최소 지원 OS**: **minSdk 21 (Android 5.0)** — 현대 AndroidX와 호환되는 실질적 하한이자 사용 중 기기 대부분을 커버. (더 낮은 버전 요구 시 라이브러리 버전 고정 별도 검토)
- **아키텍처 패턴**: MVVM.
  - `View(XML/Activity·Fragment) → ViewModel(StateFlow/LiveData 상태) → Repository → Room(DAO/Entity)`
- **저장소**: **Room** (로컬 전용). 네트워크 계층 없음.
- **네비게이션**: Jetpack Navigation Component (단일 Activity + Fragment) 또는 얕은 Activity 구성. depth를 얕게 유지한다.
- **도메인 로직 분리**: 합산·파 대비·통계 계산은 **순수 Kotlin 함수/클래스**로 분리하여 UI·DB와 독립적으로 단위 테스트한다.

### 설계 단위(경계)
- **도메인 계산 모듈**: 총타수 합산, 파 대비(홀·누적), 통계. 입력=점수/파 배열, 출력=계산값. 순수 함수.
- **저장소(Repository)**: 라운드·구장·프리셋 CRUD, 진행 중 라운드 복구, 최근 구장 조회. 인터페이스로 노출, 내부는 Room.
- **각 화면 ViewModel**: 화면 상태 보유 및 사용자 액션 처리. Repository·도메인 모듈에만 의존.

## 4. 데이터 모델 (Room)

- **Venue(구장)**: `id`, `name`, `memo?`
- **Course(코스)**: `id`, `venueId`, `name`(예: "A코스"), `pars: List<Int>` — 보통 9홀 단위. 한 구장은 1개 이상의 코스를 가질 수 있다.
- **Round(라운드)**: `id`, `date`, `venueName`(스냅샷), `players: List<String>`(1~4명), `holes: List<HoleSpec>`, `status`(진행중/완료)
  - **HoleSpec** = `(courseName, holeNo, par)`. 라운드 시작 시점의 파 구성을 **스냅샷으로 저장**하여, 이후 프리셋(Course)을 수정해도 과거 기록은 바뀌지 않는다.
- **Score**: 라운드별 `playerIndex × holeIndex → strokes: Int?` (미입력은 null 허용).
- **QuickStart/최근 설정**: 마지막으로 사용한 구장·코스 조합·플레이어 구성. 시작 화면의 "최근 구장" 원탭 재개에 사용.

> 스냅샷 원칙: Round는 자기 시점의 파·플레이어·홀 구성을 모두 자체 보유한다. Venue/Course 삭제·수정이 과거 Round에 영향을 주지 않는다.

## 5. 화면 구성 & 네비게이션

메뉴 depth를 얕게 유지하고, 한 화면에는 한 가지 작업만 배치한다.

1. **홈**: 버튼을 하나로 통합. `＋ 라운드 시작`(강조), `📋 지난 기록`, `🏳️ 내 구장 관리`.
2. **라운드 시작(선택 화면)**:
   - **최근 구장** 섹션: 가장 최근 구장을 큰 카드로 맨 위에 배치(원탭 → 지난 플레이어·홀 구성 그대로 이어받아 바로 입력). 그 아래 최근 구장 몇 개.
   - **내 구장(저장한 프리셋)** 섹션: 저장된 구장/코스 목록.
   - **주변 구장** 섹션 자리(비활성 placeholder, "M2에서 추가").
   - `＋ 새 구장 만들기`.
   - 구장/코스 선택 후: 홀 수 조합(9/18/27/36 등, 코스 이어붙이기) → 플레이어 구성(나 + 동반자 최대 3, 이름 선택) → 시작.
3. **홀 입력(핵심 화면)**: 한 홀 = 한 화면.
   - 상단: 구장명, 홀 번호, 홀 파, **누적 파 대비** 실시간 표시.
   - 플레이어별 행: `−  [ 점수 ]  ＋`.
   - 하단: `◀ 이전 홀` / `다음 홀 ▶`, `📊 전체 보기(그리드)` 진입.
4. **전체 보기(그리드, 조회 전용)**: 모든 홀 × 전원 표 + 플레이어별 합계. 셀 탭 시 해당 홀 입력 화면으로 점프하여 수정.
5. **라운드 요약/완료**: 총타수·파 대비·플레이어 순위. 라운드는 자동 저장.
6. **지난 기록**: 날짜별 목록 → 상세(그리드 조회) → 수정/삭제.
7. **내 구장 관리**: 구장·코스 생성/편집(이름, 홀별 파). 삭제.

---

## 6. 홀 입력 상호작용

- **점수 초기값 = 홀의 파.** 대부분의 홀이 파 근처이므로, 파로 끝낸 홀은 손대지 않고 "다음 홀"만 누르면 된다. 보기는 `＋` 한 번, 버디는 `−` 한 번. 하한 1타.
- **파 대비 표기(색 + 텍스트 이중)**: 언더=파랑, 파=검정/기본, 오버=빨강. 색만이 아니라 `−1 / E / +2` 텍스트를 함께 표기하여 색각 이상·고대비 모드에서도 구분 가능.
- **즉각 피드백**: 탭마다 시각 변화(+가능하면 햅틱).
- **기본 동선은 "다음 홀"**, "이전 홀"로 자유롭게 왕복하며 수정 가능.

---

## 7. 기록 & 통계 (최소)

- 라운드 완료 시 **날짜별로 자동 저장**. 지난 기록에서 목록·상세 조회.
- **간단 통계만 제공**: 최근 N라운드 평균 타수·평균 파 대비, 최고(최저타) 라운드, 최저(최고타) 라운드. 복잡한 분석·AI는 없음.

---

## 8. 오류에 관대한 설계

- 모든 홀 점수는 입력 중·완료 후 언제든 수정 가능(전체 보기에서 셀 탭 → 해당 홀).
- 삭제(라운드 단위)는 **확인 다이얼로그** 후 실행.
- 라운드 미완료 상태로 앱이 종료되어도 **진행 중 라운드를 자동 복구**하여 이어서 입력.

---

## 9. 시니어 접근성 & 기기 호환

- **큰 터치 타깃**(권장 56dp 이상), 넉넉한 간격.
- **시스템 글꼴 확대 지원**: 텍스트는 `sp` 사용, 초대형 글꼴에서도 레이아웃이 깨지지 않도록 ConstraintLayout·스크롤 대응. 긴 텍스트/버튼은 잘리지 않게 줄바꿈/축소 규칙 정의.
- **다양한 화면 비율 대응**: ConstraintLayout 제약(가이드라인·비율·퍼센트)으로 세로 길쭉/짧은 화면 모두 안정. 하드코딩된 절대 위치 지양.
- **고대비 색상 + 색·텍스트 이중 표기**. 명확한 상태 문구.
- **접근성 라벨**: 주요 상호작용 요소에 contentDescription 부여(TalkBack).
- 화면당 한 작업 원칙 유지.

## 10. 테스트 전략

- **도메인 로직(합산·파 대비·통계)**: 순수 함수로 분리하여 **단위 테스트 우선(TDD)**.
- **Repository**: in-memory Room을 이용한 테스트(라운드 저장·복구·최근 구장 조회 등).
- **핵심 플로우 UI 테스트**: 라운드 시작 → 홀 입력 → 저장 → 지난 기록 조회를 확인하는 계측 테스트 최소 1종.

---

## 11. 열린 항목 / 후속 결정

- 정확한 minSdk 확정(21 제안, 더 낮출지 여부).
- 네비게이션 방식 세부(단일 Activity + Navigation Component vs 다중 Activity).
- 통계의 "최근 N" 값(예: 최근 10라운드) 확정.
- 이 항목들은 구현 계획(writing-plans) 단계에서 확정한다.
