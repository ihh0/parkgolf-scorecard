# 파크골프 스코어 앱 — 코스 등록 위저드 & 뒤로 가기 시스템 설계서

- **작성일**: 2026-07-28
- **상위 프로젝트**: 파크골프 스코어 앱 (M1 스코어 기록 코어 위에 얹는 UI/UX 개편)
- **본 문서 범위**: 구장/코스 등록·수정 위저드 신설 + 앱 공통 상단바·뒤로 가기 확인 시스템
- **참고 목업**: `docs/mockups/템플릿 작성.make` (Figma Make, 1단계 "구장명" 화면)

---

## 1. 배경 & 목표

M1 구현 후 스모크 테스트에서 기능은 정상 동작함을 확인했다. 이어서 UI/UX를 다시 다듬기로 했고, 첫 대상으로 **구장/코스 등록 화면**을 Figma로 목업했다.

현재 `내 구장 관리`의 등록/편집은 **한 화면짜리 폼**(구장명 + 코스명 + 홀별 파를 한 번에)이다. 이를 목업에 맞춰 **4단계 위저드**(`구장명 → 코스명 → 홀 설정 → 저장`)로 재구성한다. 더불어 시니어 사용자가 뒤로 가기로 작업을 잃는 사고를 막기 위해 **앱 공통 상단바 + 뒤로 가기 확인 시스템**을 함께 도입한다.

**성공 기준**
1. 목업의 4단계 흐름으로 구장+코스 1개를 등록할 수 있다.
2. 같은 이름의 구장을 다시 등록하면 기존 구장에 코스가 통합된다.
3. 생성·수정이 같은 위저드로 처리되고, 수정 시 기존 값이 채워진다.
4. 위저드 이탈·게임 기록 이탈 시 확인 창이 떠서 실수로 작업을 잃지 않는다.
5. 구형·저사양 기기와 다양한 화면 비율에서 레이아웃이 안정적이다.

**범위 밖 (이번 작업 제외)**
- 구장 목록 화면의 시각적 재디자인 (라우팅만 코스 단위로 소폭 조정)
- 기록·그리드·요약 등 나머지 화면의 상단바 일괄 적용 (컴포넌트는 재사용형으로 준비, 적용은 후속)
- 엔티티/DB 스키마 변경

## 2. 결정 사항 요약 (브레인스토밍 확정)

| 항목 | 결정 |
|---|---|
| 코스 구조 | 위저드는 **구장+코스 1개** 생성. B·C코스는 나중에 추가 |
| 코스 추가 경로 | **같은 이름으로 위저드 재실행** → 저장 시 기존 구장에 통합 |
| 홀 설정 입력 | **기본파(파3) 일괄 + 예외 홀만 탭 조정** |
| 작업 범위 | **생성·수정 모두 위저드로** (수정 시 기존 값 채움), 목록 화면 유지 |
| 위저드 아키텍처 | **방식 A**: 단일 Fragment + ViewFlipper + 단일 draft ViewModel |
| 뒤로 가기 | 상단바 버튼과 시스템/제스처 뒤로를 **단일 경로로 통일**, 지정 구간에 확인 창 |

## 3. 화면 흐름 & 네비게이션

```
[내 구장 관리] ──＋ 새 구장──▶ 구장명 → 코스명 → 홀 설정 → 저장(확인) ──▶ [내 구장 관리]
[내 구장 관리] ──코스 탭────▶ (기존 값 채워진 위저드, 스텝 점프 가능) ──▶ [내 구장 관리]
```

- 저장 시 같은 이름 구장이 있으면 그 구장에 코스만 추가(통합), 없으면 새 구장 생성.
- 위저드는 단일 Fragment이므로 nav-graph에는 목적지 1개(`courseWizardFragment`)만 추가/교체한다.

## 4. 상단 네비게이션 바 & 뒤로 가기 시스템

### 4.1 재사용 상단바 컴포넌트
- `view_top_bar.xml` — ConstraintLayout 기반 `<include>` 컴포넌트.
- 구성: 좌측 **뒤로 가기 버튼**(56dp+ 터치 타깃, `contentDescription="뒤로"`) + **현재 작업 제목**(예: "코스 작성", "코스 편집", "게임 기록").
- 각 화면 Fragment가 제목 문자열과 뒤로 동작 핸들러를 주입한다. **홈 화면은 상단바 없음(예외).**

### 4.2 뒤로 가기 단일 경로
시스템/제스처 뒤로와 상단바 버튼이 **항상 동일하게 동작**하도록 하나의 `attemptExit()` 진입점으로 통일한다.
- 상단바 뒤로 버튼 클릭 → `attemptExit()`
- 하드웨어/제스처 뒤로 → `OnBackPressedDispatcher` 콜백 → 같은 `attemptExit()`

### 4.3 확인 창이 뜨는 구간
- **코스 위저드 (2-2)**:
  - 스텝 2·3·4에서 뒤로 → **이전 스텝**으로 이동 (확인 없음).
  - **스텝 1에서 뒤로**(= 위저드 이탈) → 확인 다이얼로그 `"코스 작성을 취소하시겠습니까?"` (수정 진입 시 `"코스 편집을 취소하시겠습니까?"`), **네 / 아니오**.
    - 네 → 목록으로 복귀. 아니오 → 위저드 유지.
- **게임 기록 / 홀 입력 (2-1)**:
  - 뒤로 → 확인 다이얼로그 `"현재 게임을 저장하지 않고 나가시겠습니까?"`, **네 / 아니오**.
    - 네 → **메인(홈)으로 이동**. 아니오 → 기록 유지.
  - 기존 홀 입력 화면에 상단바 + 이 콜백만 추가한다.

> 확인 창은 이번 범위에서 **위저드 + 홀 입력** 두 곳에 실제 적용한다. 위저드 이탈 확인은 우선 **위저드 진행 중 항상** 띄우는 것을 기본으로 하되, 추후 "입력이 있을 때만" 으로 조정 가능(후속 튜닝 항목).

## 5. 위저드 구조 (방식 A 상세)

### 5.1 구성
`CourseWizardFragment` 하나가 다음을 세로로 배치:
1. 고정 **상단바**(§4) — 제목 "코스 작성"/"코스 편집", 뒤로 버튼.
2. **스텝 인디케이터** — 4개 아이콘(구장명·코스명·홀 설정·저장) + 라벨. 현재 단계 초록 강조, **완료된 단계 아이콘 탭 시 해당 스텝으로 점프**(수정 동선 단축).
3. **본문** `ViewFlipper` — 4개 스텝 레이아웃을 담고 표시 인덱스만 전환. 어댑터가 없어 구형 기기에 가장 가벼움.
4. 하단 **`이전` / `다음`** 버튼(마지막 스텝은 `저장`). `다음`은 현재 스텝 유효성 충족 전까지 **비활성(연한 초록)** — 목업 패턴.

### 5.2 상태 (단일 draft)
`CourseWizardViewModel` 이 draft 하나를 `StateFlow`로 보유:
```kotlin
data class CourseDraft(
    val editingVenueId: Long? = null,   // 수정 진입 시 설정
    val editingCourseId: Long? = null,
    val venueName: String = "",
    val courseName: String = "",        // 기본 "A코스", 기존 구장이면 다음 글자 제안
    val holeCount: Int = 9,
    val pars: List<Int> = List(9) { 3 },
    val step: Int = 0,                  // 0..3
)
```
- 스텝 이동·필드 변경은 모두 ViewModel을 통해 draft를 갱신하고, Fragment는 상태를 관찰해 렌더링한다.

## 6. 각 단계 상호작용

1. **구장명**: 큰 입력창 + 보조문구("동일한 이름의 구장은 게임 시작 화면에서 통합 표시됩니다"). 이름이 비어있으면 `다음` 비활성.
2. **코스명**: 기본값 "A코스" 채움. **기존 구장을 이어서 등록**하는 맥락이면 다음 글자(B·C코스)를 자동 제안.
3. **홀 설정**: 홀 수(기본 9, +/− 로 조정) + 홀별 파 편집. **모든 홀이 파3에서 시작**, 파가 다른 홀만 탭해서 4·5로 변경(탭 최소화). 홀 수를 바꾸면 `pars` 길이를 맞춰 리사이즈(늘어난 칸은 파3).
4. **저장(확인)**: 구장명·코스명·홀별 파 요약을 보여주고 `저장`. 저장 후 목록으로 복귀 + 완료 스낵바.

## 7. 데이터 & 저장 로직

- 엔티티 변경 없음: `VenueEntity(id, name, memo?)`, `CourseEntity(id, venueId, name, pars: List<Int>)` 그대로. **DB 마이그레이션 불필요.**
- 저장 규칙:
  1. `editingCourseId != null` → 해당 코스 update(파·코스명), 필요 시 구장명도 반영.
  2. 아니면 같은(trim, 대소문자 무시) 이름의 구장 검색:
     - 있으면 그 `venueId` 재사용 → 코스만 추가(통합).
     - 없으면 새 `Venue` 생성 후 코스 추가.
- 기존 라운드는 이미 자기 시점의 파·플레이어·홀을 스냅샷으로 보유하므로, 코스 수정·통합이 **과거 기록에 영향을 주지 않는다.**

## 8. 수정 진입 & 목록 라우팅

- 구장 목록 화면(`MyCoursesFragment`)은 유지하되, "구장 행 탭 → 구장 편집"을 **코스 단위**로 조정:
  - 구장에 코스가 1개면 바로 위저드(해당 코스 수정)로 진입.
  - 코스가 여러 개면 코스 선택 후 위저드 진입.
  - 구장명만 바꾸려면 위저드 1단계(구장명)에서 수정.

---

## 9. 접근성 & 기기 호환

- 56dp+ 터치 타깃, `sp` 폰트, 초대형 글꼴에서도 안 깨지도록 ConstraintLayout·스크롤 대응.
- 스텝 아이콘·뒤로 버튼에 `contentDescription`, 확인 다이얼로그는 명확한 문구 + 큰 네/아니오 버튼.
- 하드코딩 절대 위치 지양(다양한 화면비 대응).

---

## 10. 테스트 전략

- **단위 테스트**
  - 저장 로직: 같은 이름 구장 통합 / 신규 구장 생성 / 기존 코스 수정 세 갈래.
  - `다음` 버튼 유효성(스텝별 조건).
  - 다음 글자 코스명 제안(A→B→C).
  - 홀 수 변경 시 `pars` 리사이즈(기본 파3 채움).
- **계측 테스트**
  - 위저드 4단계 통과 → 저장 → 목록 반영 1종.
  - 스텝 1에서 뒤로 → 확인 다이얼로그 표시 1종.

---

## 11. 후속(범위 밖, 별도 사이클)

- 상단바를 기록·그리드·요약·라운드 시작 화면에 일괄 적용.
- 나머지 화면 목업 도착 시 각각 브레인스토밍 → 설계 → 구현.
- 위저드 이탈 확인 조건 튜닝("입력이 있을 때만" 등).
